# 要件定義書 — PromptVault

## 1. 背景と課題

ChatGPT・Claude・Gemini などの LLM を業務で使う人が増え、**よく使うプロンプトを使い回す**場面が日常になりました。しかし実際には、

- メモアプリに貯めたプロンプトを探すのに時間がかかる
- 「対象読者」「文字数」などを毎回書き換える必要があり、コピー → 貼り付け → 手で修正 の手間がかかる
- 業務の機密情報を含むプロンプトを、クラウド同期のメモサービスに置きたくない

という課題がありました。

## 2. 目的

**「探す・直す・コピペする」を最速化する、オフライン完結型のプロンプト管理アプリ**を提供する。

| 目的 | 実現方法 |
|---|---|
| 探す | タイトル・本文・タグを横断するインクリメンタルサーチ、タグ絞り込み、ピン留め |
| 直す | `{{変数}}` を含むプロンプトは、コピー時に入力フォームを自動生成して置換 |
| コピペする | カードを 1 タップでクリップボードへ |
| 安心して貯める | 端末内（Hive）にのみ保存。外部サーバーへ送る経路を持たない |

## 3. 対象ユーザー

| ペルソナ | 特徴 |
|---|---|
| LLM を毎日使う会社員 | 要約・翻訳・メール下書き・コードレビューなど、型の決まった依頼を繰り返す |
| スマホで LLM を使う人 | PC のテキストエディタやスニペットツールが使えない環境で、素早く貼り付けたい |
| 機密情報を扱う人 | クラウド同期サービスに業務のプロンプトを置けない |

## 4. 機能要件

| ID | 機能 | 内容 | プラン |
|---|---|---|---|
| F-01 | プロンプトの作成・編集 | タイトル・本文・タグ。全画面エディタ | Free（件数無制限） |
| F-02 | 変数の挿入 | よく使う変数チップ・カスタム変数をカーソル位置に挿入 | Free |
| F-03 | 検索 | タイトル・本文・タグ横断、空白区切り AND、大文字小文字を区別しない | Free |
| F-04 | タグ絞り込み | 複数タグの AND | Free |
| F-05 | 並び替え | 最近使った順 ／ よく使う順（ピン留めは常に先頭） | Free |
| F-06 | ピン留め | 件数無制限 | Free |
| F-07 | 1 タップコピー | カードのタップでクリップボードへ | Free |
| F-08 | 変数フォーム | `{{変数}}` の入力欄を自動生成し、置換してコピー | Free |
| F-09 | 選択肢・既定値 | `{{トーン:丁寧\|カジュアル}}` / `{{文字数=200}}` | **Pro** |
| F-10 | コピー履歴 | 置換後のテキストを最大 20 件保持し、再コピー | **Pro** |
| F-11 | 取り消し | 削除・編集・全件削除を SnackBar の「元に戻す」で取り消し | Free |
| F-12 | 複製 | 既存のプロンプトを「◯◯ のコピー」として複製 | Free |
| F-13 | JSON 書き出し | 共有シートで端末・クラウドドライブに保存 | Free |
| F-14 | JSON 復元 | 追加（マージ）／置き換えを選択 | **Pro** |
| F-15 | 初回サンプル | 初回起動時に変数入りサンプルを 3 件投入 | Free |
| F-16 | 広告 | バナー＋インタースティシャル（4 回に 1 回・2 分空ける） | Free のみ |
| F-17 | Pro 購入・復元 | 買い切り | — |

### プラン設計の考え方

**ユーザー自身のデータには制限をかけない。** 保存件数やピン留めを制限すると、価値を体験する前に離脱されるか、「データを失った」という最悪の体験を生みます。課金の理由は「広告が消える」と「入力がさらに速くなる」に置きました。

## 5. 非機能要件

| 区分 | 要件 | 実現方法 |
|---|---|---|
| 機密性 | プロンプト本文を外部に送らない | 保存先は Hive のみ。送信経路をアプリ内に持たない |
| 可用性 | データを失わない | 書き出しは Free でも無制限。削除はすべて取り消し可能 |
| 使いやすさ | コピーまでの操作を最短にする | カード 1 タップ。削除に確認ダイアログを挟まない |
| 使いやすさ | 並び順を勝手に変えない | コピー・ピン留めでは `updatedAt` を更新しない |
| 使いやすさ | 広告でコピー体験を損なわない | 広告はコピー完了後に表示。頻度を二重に制限 |
| 互換性 | 古い保存形式を読める | Hive のフィールド番号を据え置き、旧カテゴリをタグへ移行 |
| 保守性 | 機能差を 1 か所で管理 | `Entitlements` に集約 |
| 保守性 | テストで仕様を固定 | 単体・結合（実 Hive）・ウィジェットテスト 143 件 |
| 運用コスト | サーバー費 0 円 | サーバーを持たない |

## 6. あえて削ったもの

| 削ったもの | 理由 |
|---|---|
| カテゴリ（タグと併存していた） | 入力欄が 2 つあると保存が億劫になり、「素早く貯める」と噛み合わない。タグに一本化し、既存データは自動移行 |
| 並び替え 5 種類 | 実際に使い分けられるのは「最近使った順」「よく使う順」の 2 つだけだった |
| 「発見」タブと下部タブ | 一覧をホームに直結し、縦の表示領域をタブバー 1 本分広げた |
| 削除の確認ダイアログ | 1 タップで消して 1 タップで戻せるほうが速い |
| 保存件数・ピン留めの上限 | ユーザーのデータを人質に取らない |
